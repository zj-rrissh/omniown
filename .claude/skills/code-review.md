# code-review — 代码审查

## 触发条件
- 用户说"review"、"审查代码"、"检查 PR"
- 每次提交前

## 审查维度（按优先级）

### 1. 正确性
- 逻辑是否正确？边界条件是否处理？
- 跨进程数据流是否正确？（Tauri env → Node.js → Rust CLI args）
- 路径解析在 dev/打包两种模式下都正确？

### 2. 安全性
- 无硬编码密钥？API key 是否脱敏？
- 用户输入是否校验？
- 错误信息是否泄露敏感数据？

### 3. 可靠性
- 错误处理是否完备？（Rust: `Result`，Node.js: try/catch）
- 资源是否正确释放？（子进程、文件句柄、数据库连接）
- 并发安全？（SQLite WAL 模式）

### 4. 性能
- 无 N+1 查询？
- 文件监听去重机制工作正常？
- 大文件处理有截断保护？

### 5. 可维护性
- 命名清晰？单一职责？
- 与现有代码风格一致？
- 无死代码残留？

## 报告格式

```markdown
### [严重度] 问题描述
- **文件**: path/to/file:line
- **证据**: 具体代码片段
- **影响**: 实际后果
- **建议**: 修复方案
```

严重度：CRITICAL / HIGH / MEDIUM / LOW
